# Contributing

Thank you for helping improve the NDR Infotech website. This guide explains how the project is organised and how to make changes safely.

By contributing you agree that your contribution becomes part of the project under the terms in [LICENSE](LICENSE). Contributions are accepted only from people invited by the maintainers.

## Project structure

```
/            HTML pages (index, about, services, technologies, talent, wealth, contact, ...)
css/         Stylesheets (styles.css plus one file per page group)
js/          Scripts (site-wide script.js, hero animations, page-specific files)
images/      Logo, favicon and other images
py/          Page generators (build.py, build_home.py) and their data
docs/        Project notes
CNAME        Custom domain for GitHub Pages (www.ndrinfotech.com)
```

Most inner pages (About, Services, Technologies, Talent, Wealth, Contact, Privacy, Terms and the service pages) are **generated** by `py/build.py`. The home page body is generated by `py/build_home.py`.

> **Do not edit the generated HTML files by hand for content changes.** Edit the generator in `py/` and rebuild, otherwise your edit is overwritten the next time the pages are built.

## Running the site locally

You need Python 3.

```bash
# from the project root
py -m http.server 8765        # Windows
python3 -m http.server 8765   # macOS / Linux
```

Open <http://localhost:8765>.

## Rebuilding the pages

After changing anything in `py/`:

```bash
py py/build.py
py py/build_home.py
```

Review the changed files with `git diff` before committing.

## Making a change

1. Create a branch from `main`, for example `feature/wealth-faq` or `fix/mobile-menu`.
2. Make your change in small, focused commits.
3. Rebuild the pages if you changed the generators.
4. Test locally (see the checklist below).
5. Open a pull request describing what changed and why, with screenshots for visual changes.
6. A maintainer reviews and merges. Merging to `main` publishes the site through GitHub Pages.

Commit messages should be short and in the imperative mood, for example: `Fix overlapping cards on mobile`.

## Checklist before opening a pull request

- [ ] Pages open without errors on desktop and on a phone-width window
- [ ] Layout works from about 360px to wide desktop screens
- [ ] Animations still play, and the page works when "reduce motion" is on
- [ ] Links, menu and the contact form work
- [ ] No broken paths: stylesheets are in `css/`, scripts in `js/`, images in `images/`
- [ ] No console errors

## Content and style guidelines

- Keep the existing light theme and the cyan and violet accent colours (set in `:root` of `css/styles.css`).
- Do not state specific statistics or numeric claims (years of experience, counts of services or clients) in page copy.
- Use thin-line SVG icons from `py/icons.py` to stay consistent.
- Respect accessibility: meaningful text for images, good contrast, keyboard access, and `prefers-reduced-motion` support for new animations.
- Keep performance in mind on phones: avoid heavy blur filters and endless animations on large areas.
- Use plain, professional language. Check spelling before committing.

## Contact form

The contact form sends enquiries to the company inbox through [FormSubmit](https://formsubmit.co). Do not change the destination address or the validation rules (mobile number required, no links in name or message) without maintainer approval.

## Security and secrets

This repository is **public**.

- Never commit passwords, API keys, tokens, private email content or customer data.
- If you find a security problem, do not open a public issue. Contact the maintainer directly (see [AUTHORS.md](AUTHORS.md)).

## Releases

Maintainers tag releases using semantic versions: `v1.0.1` for fixes and `v1.1.0` for new features, and publish release notes on the GitHub Releases page.

## Reporting bugs and suggesting changes

Open a GitHub issue with:

- what you expected and what happened
- the page address and your device/browser
- a screenshot if it is a visual problem
